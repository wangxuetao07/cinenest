# 影巢 CineNest

> 把你的硬盘变成私人影院。

本地运行的私人视频网站。添加任意本地目录作为媒体库，自动扫描视频、提取元数据、生成缩略图，在浏览器里像主流视频网站一样浏览与播放，支持进度记忆、继续观看、搜索、收藏与播放列表。

- 目标平台：Windows 10 / 11
- 访问地址：`http://localhost:8080` 或 `http://<局域网IP>:8080`
- 技术栈：Node.js + Express + better-sqlite3 / Vue 3 + Vite + Tailwind CSS + Naive UI + Artplayer

## 一键部署包（推荐，最快上手）

不想碰命令行？直接使用**一键部署包**：解压 → 双击 → 自动打开浏览器，全程无需 `npm install`、无需手动配置 FFmpeg。

### 1. 获取部署包

| 包名 | 体积 | 适用场景 |
|---|---|---|
| `CineNest-Deploy-v1.4.9-win-x64.zip` | 约 11 MB | **推荐**。不含 FFmpeg，首次启动自动下载（需联网） |
| `CineNest-Deploy-v1.4.9-offline-win-x64.zip` | 约 137 MB | 目标机器**不能联网**时使用，内置 FFmpeg 与全部依赖 |

两个包都自带已构建好的前端 `dist/`、运行依赖 `node_modules/`，以及适配 Node 20/22/23/24/25 的多版本原生组件 `vendor/`，只需目标机器装好 Node.js。

> 需要重新生成部署包时，在项目根目录执行：
> ```bash
> npm run deploy:pack            # 生成标准包 + 离线包
> npm run deploy:pack -- --standard   # 只生成标准包
> npm run deploy:pack -- --offline    # 只生成离线包
> ```

### 2. 安装与启动（三步）

1. **解压**到任意目录，例如 `D:\CineNest`（支持中文路径，建议路径不含空格与特殊符号）；
2. **安装 Node.js**：若本机已有 20.10+ 可跳过；否则到 <https://nodejs.org/> 下载 **LTS 版**（推荐 22.x / 24.x）一路下一步；
3. **双击包内的 `start.cmd`**（包内文件名统一使用英文，避免不同解压工具的中文编码差异）：

```text
============================================================
   影巢 CineNest  ·  一键启动
============================================================
   安装目录 : D:\CineNest
   Node.js  : v24.15.0 (win32-x64, ABI 137)
   服务端口 : 8080（来自 默认值）

  [OK]   Node.js 版本 v24.15.0 符合要求
  [OK]   已自动适配当前 Node.js（node-v137-win32-x64）
  [OK]   FFmpeg 就绪（包内 bin/ffmpeg）
  [..]   正在启动 CineNest 服务 ...
============================================================
   启动成功！请在浏览器访问： http://localhost:8080
   首次启动会自动创建默认管理员账号（用户名/密码见上方日志）
   关闭本窗口即可停止服务（或按 Ctrl+C）
============================================================
```

启动器会自动完成：**环境自检 → 依赖自愈 → FFmpeg 补全 → 启动服务 → 打开浏览器**。首次启动部署约 1~3 分钟（装依赖 / 下载 FFmpeg），之后每次启动**数秒即就绪**。首次启动后终端会打印默认管理员账号与密码，请登录后及时修改。

### 3. 启动参数与日常操作

| 操作 | 命令 / 方式 |
|---|---|
| 启动 | 双击 `start.cmd` |
| 停止 | 关闭服务窗口，或在窗口内按 `Ctrl + C` |
| 换端口 | 改根目录 `.env` 里的 `PORT=8090`（持久），或 `start.cmd --port 8090`（仅本次） |
| 不自动开浏览器 | `start.cmd --no-open` |
| 只做环境自检（不启动） | `start.cmd --check` |
| 禁止自动下载 FFmpeg | `start.cmd --no-download` |
| 局域网访问 | 手机连同一 Wi-Fi，访问 `http://电脑IP:8080`（需放行防火墙） |

> 包内 `DEPLOY-README.md` 提供了同内容的离线速查版，可随包分发。包内所有文件名均为英文（`start.cmd`、`launcher.cjs`、`DEPLOY-README.md`），这是为了避免中文文件名在不同解压工具与系统代码页下出现乱码或被跳过；程序与媒体库**依然完整支持中文路径与中文文件名**。

#### 端口与监听地址的取值优先级

从高到低，先命中者生效：

| 优先级 | 来源 | 示例 |
|---|---|---|
| 1 | 命令行参数 | `start.cmd --port 8090` |
| 2 | 系统环境变量 `PORT` | `set PORT=8090` 后启动 |
| 3 | 根目录 `.env` 文件 | `PORT=8090` |
| 4 | 内置默认值 | `8080` |

启动横幅会直接标注本次端口来源，例如 `服务端口 : 8090（来自 .env 文件）`，可据此确认配置是否被读到。`HOST` 同理，但只从 `.env` / 环境变量读取（默认 `0.0.0.0`）。开发模式（`npm run dev` / `npm start`）不经过启动器，同样按上表 2→4 的顺序取值。

根目录的 `.env` 需要你自己建：把同目录的 `.env.example` 复制一份、重命名为 `.env` 再改（`.env` 属本机私有配置，不入版本库）。

### 4. 针对不同环境的自动处理

- **已装过 FFmpeg**：启动器按「包内 `bin/ffmpeg` → 系统 PATH」顺序查找，命中即直接用，不重复下载；
- **Node.js 大版本不同**（最容易踩的坑）：`better-sqlite3` 是**原生模块**，走 V8 ABI，Node 大版本一变就无法加载。部署包已内置 **Node 20 / 22 / 23 / 24 / 25** 五个大版本对应的原生组件（`vendor/` 目录），启动器按当前 ABI 自动切换，**免联网、免编译、瞬时完成**——同一个包换台机器、换 Node 版本都能直接跑；
- **Node 版本不在上述范围**（如 18 或 26+）：启动器会打印含 ABI 编号的明确提示，并推荐安装 Node 22 LTS；也会尝试联网重装依赖作为兜底；
- **离线环境**：用离线包即可，**无需**与打包机的 Node 版本一致；
- **数据与升级**：升级只需解压新包覆盖代码，保留 `data/` 目录即可（媒体库、标签、收藏、观看进度都在其中）。

## 二、安装 FFmpeg（必做）

本项目不自带 FFmpeg，需手动下载并放到指定目录。

1. 下载 Windows 静态版（任选其一）：
   - https://www.gyan.dev/ffmpeg/builds/ffmpeg-release-essentials.zip
   - https://github.com/BtbN/FFmpeg-Builds/releases （选 `ffmpeg-master-latest-win64-gpl.zip`）
2. 解压后进入 `bin/` 目录，找到 `ffmpeg.exe` 与 `ffprobe.exe`。
3. 把这两个文件复制到项目的：

   ```
   cinenest/bin/ffmpeg/
   ├─ ffmpeg.exe
   └─ ffprobe.exe
   ```

4. 验证：

   ```bash
   ./bin/ffmpeg/ffmpeg.exe -version
   ./bin/ffmpeg/ffprobe.exe -version
   ```

> 启动时程序会检查这两个文件。缺失时会打印明确错误并退出，并给出下载地址。
> 若 `bin/ffmpeg/` 下没有，程序会回退到系统 `PATH` 中查找 `ffmpeg` / `ffprobe`。

> **注意**：`bin/ffmpeg/` **不在版本库中**（两个 exe 合计约 337MB，单文件已超过 GitHub 的 100MB 上限）。
> 从仓库克隆后需要按上面步骤手动放置；若只是要打离线部署包，直接跑 `node build-deploy.cjs` 即可——
> 检测到缺失时会自动下载补齐（内网可设环境变量 `CINENEST_FFMPEG_MIRROR` 指向自有镜像，多个用 `|` 分隔）。

## 四、启动

```bash

npm run dev
```

浏览器访问 <http://localhost:5173>

## 五、首次使用

1. 打开浏览器访问 `http://localhost:8080`，会先进入**登录页**。
2. 用默认管理员账号登录：**用户名 `admin`，密码 `admin123`**（仅数据库中没有任何账号时才会自动创建，启动日志中也会高亮提示）。**登录后请立即在右上角头像 → 修改密码**。
3. 打开「设置 → 媒体库 → 新增媒体库」，填写名称与**目录绝对路径**（例如 `D:\Movies`），保存。
4. 点击该媒体库的「扫描」按钮（或到「扫描任务」页点「立即扫描」）。
5. 扫描完成后回首页，即可看到影片卡片。

- 支持的视频格式：`.mp4 .mkv .avi .mov .wmv .flv .webm .m4v .ts .mpg .mpeg .m3u8 .m3u`
- 支持的字幕格式：`.srt .ass .vtt`（与视频**同名**且位于同目录，会自动转换为 WebVTT 加载；播放器控制栏有「字幕」按钮可随时开关，见下节）
- 默认每天凌晨 3 点自动扫描一次（可在媒体库设置里改 cron 表达式）
- 目录内文件变动会自动触发扫描（防抖 3 秒）

## 五点七、播放器字幕开关（v1.2.1 新增）

- 只要视频同目录存在**同名**字幕文件（`xxx.srt / .ass / .vtt`），播放时控制栏右侧会出现「字幕」按钮：
  - **字幕 开**（主题色高亮）：正在显示字幕，点击即关闭；
  - **字幕 关**：已关闭，点击即恢复显示。切换时会弹出「字幕已开启 / 字幕已关闭」提示。
- **开关会被记住**（存在浏览器本地），刷新页面、换片、下次打开都保持上次的选择；默认开启。
- 没有同名字幕的视频：按钮置灰显示「字幕」，点击会提示「这个视频没有同名字幕文件」。
- 浏览器放不了的格式自动转码播放时，字幕同样可用（播放器重建后字幕会自动重新挂载）。

## 五点八、标签搜索与播放页标签编辑（v1.2.2 新增）

- **搜索覆盖标签**：搜索框输入关键词，会在**标题 / 文件名 / 标签名**三处任一命中即算匹配（例如给视频打了「夜晚」标签，直接搜「夜晚」就能找到）。搜索框下方会实时显示**搜索条件**（关键词、标签，均可一键移除）与匹配范围。
- **按标签筛选**：搜索页支持 `?tag=标签名` 精确筛选；与关键词叠加时取交集。
- **标签可点击**：播放页、详情页、搜索结果卡片上的标签都是按钮，点击即跳到「按该标签搜索」；结果卡片上会展示该片的标签，**命中的标签用主题色高亮**，统计行会标注「N 个由标签命中」。
- **播放页直接编辑标签（仅管理员）**：播放页信息区新增「编辑 / + 添加标签」入口，回车新建、点 ✕ 删除，保存后立即生效并参与搜索（与详情页一致，服务端同样限制仅管理员）。

## 五点九、多关键词搜索（v1.2.3 新增）

- **空格分隔、任一命中即显示**：关键词以空格（半角 / 全角空格均可）分隔，多个关键词之间是**「或」**的关系 —— 在标题 / 文件名 / 标签任一位置命中**任意一个**关键词，该影片就会出现在结果里（例如「夜晚 美好」会同时返回只带「夜晚」标签和只带「美好」标签的影片）。
- **命中越多越靠前**：结果按命中关键词个数降序排列；完整短语命中标题的仍排最前。单次最多拆 8 个关键词（自动去重、忽略大小写）。
- **搜索条件逐词展示**：搜索框下方把每个关键词显示为独立、可单独移除的条件项，并提示「N 个关键词之间为『或』关系，任一命中即显示」；移除某个关键词后其余条件立即重新搜索。

## 五点十、移动端适配（v1.2.4 新增）

CineNest 在手机 / 平板浏览器上开箱即用，桌面端布局不受影响：

- **抽屉式导航**：窄屏（<1024px）下侧边栏收为抽屉，点顶栏汉堡按钮滑出；点遮罩、抽屉内 ✕ 或跳转页面后自动收起。桌面端仍是固定侧边栏（可折叠）。
- **自动重排**：首页 Hero 轮播、视频网格（手机一行两列）、横向滑动海报行（触屏滑动翻页）、筛选栏、播放页信息区、详情页按钮、继续观看 / 播放列表条目、媒体库卡片等在窄屏下自动换行重排，全程无横向滚动条。
- **管理表格**：用户管理、扫描任务在手机上改为表格容器内横向滚动。
- **播放体验**：播放器控制栏紧凑化、字幕字号加大；视频自动内联播放（playsInline），支持全屏。控制栏按钮按可用宽度**自动增减**（空间不足时依次收起画中画 / 设置 / 下一个，始终保住全屏按钮，空间充裕时自动恢复）；手机上收起音量滑杆（用系统音量键）与「网页全屏」（与原生全屏重复）；播放器在手机上为贴边直角、全屏时无圆角。
- **输入与手势**：输入框字号 ≥16px（避免 iOS 聚焦自动缩放）、关闭触屏点击高亮、横向滑动不带动整页、适配刘海屏安全区；页面高度用 `100dvh` 跟随移动端浏览器地址栏。
- 直接用手机浏览器访问 `http://<电脑IP>:8080` 即可使用（与设置页提示的局域网地址一致）。

## 五点十一、进度条抽帧预览与增删安全网（v1.3 新增）

### 进度条抽帧预览

播放时把鼠标悬停在进度条上（手机按住拖动），会弹出对应时间点的画面缩略图，不用来回拖动确认内容：

- **自动生成**：首次打开某个视频时后台自动抽帧（不阻塞播放）；管理员也可在「设置 → 系统」点「生成预览图（抽帧）」一次性补齐全部存量，带实时进度、可取消。
- **质量**：短视频全解抽帧、长视频按实际关键帧数定帧数，保证每一格都有画面；Windows 上启用显卡硬解，4K 片源约 1 分钟/片、720p 秒级。全部完成后每片仅约 275KB。
- **手机端**：按住进度条拖动即可边拖边看（播放器已接管触摸手势，不会误触发页面滚动）。
- 生成失败不影响播放，只是不显示预览。

### 视频增删更安全

- **存储离线保护**：如果媒体库放在外接盘 / NAS 上，盘没挂载时以前的扫描会把整库记录连同标签、收藏、观看进度一起清空。现在扫描发现大面积文件缺失（超 30% 或全部）会**跳过删除**，并在「扫描任务」页顶部显示告警，确认文件确实已移除后点「确认清理」才会真正删除。
- **缓存跟着删**：删视频、删媒体库、重扫清理时自动清掉对应的缩略图与预览图，不再留垃圾文件；设置页新增「清理孤儿缓存」一键回收历史残留。
- **缩略图不再显示旧图**：缩略图地址带版本指纹，源文件被替换后浏览器立即拿到新图。

## 五点十二、卡片悬停播放预览（v1.4 新增）

**鼠标悬停在首页 / 媒体库 / 搜索结果的影片卡片上，约 0.35 秒后自动静音循环播放预览片段**——类 B 站体验：

- **预览内容**：全片均匀取 5 段 × 2 秒拼接（片头之后、片尾之前均匀分布），比只看片头更能代表内容；短片（<12 秒）直接播整片。
- **秒开**：每个视频预生成一个约 200KB 的 480p 小片段（H.264，全平台可解、边下边播），悬停时不碰原片、不占转码资源——4K HEVC 片源也能秒开（浏览器本身不支持 HEVC，直连原片是放不出来的）。
- **生成时机全自动**：扫描完成后后台自动补齐新视频；没来得及生成的，悬停时会悄悄触发生成（本次保持静态封面，下次悬停即可播放）；管理员也可在「设置 → 系统」点「生成悬停预览」一次性补齐，带进度、可取消。全库约 7 分钟、总占用约 20MB。
- **性能保护**：同一时刻只播一张卡片（划过一排不会同时拉流）；起播前保持静态封面不闪黑；移开立即停止；触屏设备完全不启用。
- 悬停预览与 v1.3 的「进度条抽帧预览」互不影响，两者同时可用。

## 五点十三、视频重命名：显示名与磁盘文件同步改（v1.4.8 新增，仅管理员）

**详情页标题旁、播放页操作栏新增「重命名」按钮**，改的不只是显示名——**磁盘上的文件会一并改名**：

- **改动三同步**：数据库记录（路径 / 文件名 / 显示名）、磁盘文件、同目录**同名字幕**（`影片.srt`、`影片.zh-CN.srt` / `影片.chs.ass` 这类带语言标记的也会保留标记跟着改）一次完成；缩略图缓存直接迁移键位，**不会重新抽帧**。
- **视频 ID 不变**：收藏、观看进度、观看历史、播放列表、标签全部保留，正在播放时改名也不会中断画面。
- **名字规则**：不能含 `\ / : * ? " < > |`、不能以点或空格结尾、不用系统保留名（CON 等）、最长 120 字符；**扩展名固定不可改**（输入里带上相同扩展名会自动剥离）；与已有文件重名会被拒绝。
- **弹窗里可取消勾选「同时重命名磁盘上的文件」**：只想改站内显示名、不动硬盘文件时用这个。
- **占用保护**：文件正被播放器 / 预览生成占用时会自动稍候重试，仍失败会提示「文件被占用」稍后再试；改名后不会触发多余的全库扫描。

## 五点四、m3u8 / HLS 播放（v1.2 新增）

CineNest 对 m3u8 有两条路径，**自动选择，无需配置**：

1. **本地 HLS 素材**：媒体库里本身就是 HLS 的（`xxx.m3u8` + 同目录 `.ts` 分片），会作为一个影片被索引；播放时后端把播放列表重写成可访问的地址，分片原样直出（支持拖拽 / Range）。注意 `.m3u8` **同目录**的 `.ts / .m4s / .aac` 分片不会被当成独立影片重复索引。
2. **浏览器放不了的普通视频**（`mkv` / `avi` / `wmv` / `flv` / HEVC 等）：播放器检测到浏览器无法直出后，会**自动切换到实时转码 HLS**（H.264 + AAC，6 秒分片），播放页下方会出现「实时转码（HLS）播放中」提示。

> 转码说明：转码进行中即可从头播放并**任意拖拽**（服务端会等你拖到的位置生成好对应分片，最长等 30 秒）；一个视频同时只转一份，全站最多 2 路并发，30 分钟无人观看自动回收。转码临时文件在 `data/hls/`，重启服务自动清空。
> 如果 CPU 吃紧，可在 `server/services/hls.js` 顶部把 `MAX_TRANSCODES` 调小，或把 `-preset veryfast` 改成 `ultrafast`。

## 五点五、登录与用户权限（v1.1 新增）

- **登录**：所有页面与接口均需登录。会话以 HttpOnly Cookie 下发，有效期 30 天，右上角头像 →「退出登录」可注销。
- **两种角色**：
  - **管理员**：全部功能 —— 首页 / 继续观看 / 收藏 / 播放列表 / 搜索 / **扫描任务 / 设置 / 用户管理**。
  - **普通用户**：仅观看相关功能，**看不到扫描任务、设置、用户管理**；服务端同样拒绝（403），不是仅隐藏菜单。
- **用户管理（仅管理员）**：新增用户（用户名 / 显示名 / 密码 / 角色）、启用停用、重置密码（对方会被强制下线）、删除、切换管理员与普通身份。不能停用/删除/降级自己，系统始终保留至少一个启用状态的管理员。
- **忘记 admin 密码**：关闭服务后删除 `data/cinenest.db` 中 `user` 表的 admin 行（或直接删除整个 `data/cinenest.db`，媒体库与播放记录会一并清空，慎用），重启服务会重新创建 `admin / admin123`：

  ```sql
  DELETE FROM user WHERE username = 'admin';
  ```

## 五点六、多用户数据隔离与媒体库启停（v1.2 新增）

- **收藏 / 观看进度 / 历史记录 / 播放列表都是每个账号一份**，互不可见、互不影响。首次升级到 v1.2 时，v1.1 里「全站共享」的这些数据会自动归属给管理员账号（只迁移一次，迁移前自动备份到 `data/backup/`）。
- **媒体库可以停用**：管理员在「设置 → 媒体库」编辑某个库，把「启用」开关关掉即可。
  - 停用后该库的视频**立即从首页、媒体库页、搜索、收藏、历史、播放列表中消失**（服务端过滤）。
  - 管理员侧边栏仍能看到该库（带「停用」徽标），方便回来重新启用；普通用户则完全看不到。
  - 停用不删除任何文件或记录，重新打开「启用」即恢复。
- **标题 / 标签由管理员维护**：这两项属于全站共享的元数据，普通用户不可修改（详情页对他们只读展示）。

## 七、开机自启（pm2）

```bash
# 1. 全局安装 pm2
npm install -g pm2

# 2. 启动服务
cd D:\project\cinenest
pm2 start server/index.js --name cinenest

# 3. 保存当前进程列表
pm2 save

# 4. 生成开机自启（Windows 使用 pm2-windows-startup）
npm install -g pm2-windows-startup
pm2-startup install
pm2 save
```

常用命令：

```bash
pm2 status            # 查看状态
pm2 logs cinenest     # 查看日志
pm2 restart cinenest  # 重启
pm2 stop cinenest     # 停止
pm2 delete cinenest   # 移除
```

## 九、常见问题

### 1. ffmpeg 缺失

**现象**：启动即退出，终端打印「启动失败：缺少外部依赖 ffmpeg.exe」。
**处理**：按第二节把 `ffmpeg.exe`、`ffprobe.exe` 放到 `bin/ffmpeg/`。

### 2. 端口 8080 被占用

**现象**：启动报 `EADDRINUSE`。
**处理**：查看占用进程并结束，或改端口。

```bash
netstat -ano | findstr :8080
taskkill /PID <进程PID> /F
```

改用其他端口（二选一）：

- **持久生效**：编辑根目录 `.env`，把 `PORT=8080` 改成如 `PORT=8090`，重启服务；
- **仅本次生效**：`start.cmd --port 8090`。

重启后看启动横幅那一行 `服务端口 : xxxx（来自 ...）`，确认值来自哪里。若是开发模式（`npm run dev`），`.env` 会被直接读取，改完重启即可生效。

### 3. 中文乱码 / 中文文件名扫不到

- 项目所有文件读写默认 UTF-8，HTTP 响应头带 `charset=utf-8`。
- 若终端显示乱码，多为终端编码问题，浏览器页面显示正常即可。
- 中文目录、中文文件名已支持；若仍扫不到，请确认目录路径填写的是**绝对路径**且确实存在。
- 大量中文文件名建议确认磁盘文件系统为 NTFS（FAT32 对长文件名/特殊字符支持较差）。

### 4. PowerShell 里跑 npm 报「禁止运行脚本」

**现象**：

```
npm : 无法加载文件 D:\Program Files\nodejs\npm.ps1，因为在此系统上禁止运行脚本。
    + CategoryInfo : SecurityError: (:) [], PSSecurityException
```

**原因**：PowerShell 默认执行策略为 `Restricted`，禁止运行任何 `.ps1`，而 PowerShell 里的 `npm` 会优先命中 `npm.ps1`。与项目无关。

**处理**（任选其一）：

```powershell
# ① 最省事：直接用 npm.cmd（.cmd 由 cmd.exe 执行，不受执行策略管辖）
npm.cmd run dev

# ② 一劳永逸：只放开当前用户，仍会阻止从网上下载的未签名脚本
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned

# ③ 换个 shell：在 Git Bash 里直接 npm run dev
```

### 5. 启动报 NODE_MODULE_VERSION / ERR_DLOPEN_FAILED

**现象**：

```
Error: The module '...\better_sqlite3.node' was compiled against a different Node.js version
using NODE_MODULE_VERSION 127. This version of Node.js requires NODE_MODULE_VERSION 137.
```

**原因**：原生模块的 ABI 与当前 Node 大版本不匹配。**正常情况下项目会自动处理**（`server/utils/nativeAbi.js` 启动时按 `process.versions.modules` 从 `vendor/sqlite3/` 落位对应组件）。若仍报错：

1. 确认 `vendor/sqlite3/node-v<ABI>-win32-x64/better_sqlite3.node` 存在（当前 Node 的 ABI 见上表：20→115、22→127、23→131、24→137、25→141）；
2. 该文件可能被另一个正在运行的 CineNest 进程占用 → 先关掉所有 CineNest 窗口再启动；
3. 你的 Node 不在 20/22/23/24/25 之列（如 26+ 或 18）→ 换用 Node 22 LTS，或执行 `npm install`（需联网 + C++ 编译环境）自行编译。

### 6. 安装 better-sqlite3 失败

**现象**：`npm install` 报 node-gyp / MSBuild 相关错误。
**处理**：安装 **Visual Studio Build Tools**（勾选「使用 C++ 的桌面开发」），或切换到与本机 Node 版本匹配的预编译包后重试。多数情况下走上面的自动适配即可，不必自己编译。

### 7. 视频无法播放 / 一直转圈

- 确认容器格式浏览器支持：`.mp4`(H.264/AAC) 兼容性最好。
- `.mkv`、`.avi`、`wmv`、`flv` 等浏览器无法直出的格式，v1.2 起会**自动切换到实时转码 HLS** 播放：首帧需要几秒，拖拽到未转码的位置需要等服务端补齐分片。
- 若转码很卡，多半是 CPU 不够（尤其 4K 片源），可降低并发或换 `ultrafast` 预设（见「五点四」）。
- 检查 `data/error.log` 是否有读取错误。

### 8. 缩略图不显示

- 首次扫描时生成，大库会稍慢；未生成的会在首次访问 `/api/thumb/:id` 时按需补生成。
- 可在「设置 → 系统」点击「清空缩略图缓存」后重新扫描。
